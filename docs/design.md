# typofix 设计说明

## 目标

在 30 万条合并词典上，为每条查询找出所有加权代价 `cost ≤ 8` 的词条，按固定
公式打分、按固定规则排序返回前 N 条；结果必须与逐条全量 DP 扫描完全一致，
同时满足加载 ≤ 15 s、`tracemalloc` 峰值 ≤ 400 MiB、p95 ≤ 200 ms、最坏
≤ 800 ms。

## 代价模型（`typofix/cost.py`）

在 `casefold()` 后的串上做加权 restricted Damerau（OSA）动态规划：

- 替换 4；QWERTY 邻键替换 2（仅小写 ASCII 字母，码点表见代码）；
- 插入 / 删除 3，词首词尾词中同价；相邻换位 2，换位字符不再参与其它编辑。

`edit_cost(query, word, limit)` 带可证明安全的早退：当前行最小值 > 上限，
且上一行最小值 + 2（换位代价）> 上限时，后续行不可能回到上限内，直接返回
`limit + 1`；不超过上限时返回精确代价。邻键表以 README 原文为准，表中存在
6 处单向条目，物理邻接本身对称，代码取对称闭包。

## 索引（`typofix/engine.py`）

30 万条逐条 DP 不可行（p95 预算下每秒只能做几千次比较）。采用
SymSpell 式“删除签名”哈希索引，再用精确 DP 复核候选，因此召回与全量扫描
等价，索引只负责缩小候选集。

### 为什么删 2 个字符的签名就够

把换位、邻键替换称为“廉价操作”（代价 2），增删 3，普通替换 4。
代价 ≤ 8 时最多容纳 4 个操作：

- 0–2 个操作：单位 Damerau 距离 ≤ 2，经典引理保证
  `deletes(query, 2) ∩ deletes(word, 2)` 非空；
- 3 个操作：预算内的组合（2+2+2、2+2+3、2+2+4、2+3+3）必含至少一个
  廉价操作。先对查询应用该廉价操作，剩余 ≤ 2 个操作，仍被删 2 签名覆盖；
- 4 个操作：只有 2+2+2+2=8，即 4 个廉价操作。先对查询应用其中两个，
  剩余 2 个操作同样被覆盖。

因此查询侧的签名来自：查询本身、应用 1 个廉价操作后的所有变体
（邻键替换 / 相邻换位），以及应用 2 个互不相交廉价操作后的所有变体；
对每个变体再取删 0/1/2 字符的全部串。

词典侧对每个词条预计算同样的删 0/1/2 签名。两侧哈希一致即进入候选集，
随后一律用 `edit_cost` 精确复核：哈希碰撞、签名超集带来的假候选都会被
DP 滤掉，代价与排序不受索引影响。

### 存储

- 词条按 casefold 键码点序编号，存原始词形、归一键、频次、频次项。
- 每个签名把 Python 字符串哈希截到 44 位，`(38 位低位 << 19) | 词条 id`
  打包成一个 64 位整数，按哈希高 6 位分成 64 个有序 `array('q')`。
  查询时两次二分定位 posting。哈希碰撞只产生假候选，由 DP 复核排除。
- 全量约 713 万个签名，索引约 57 MiB；64 分片让构建期只需对小表排序，
  `tracemalloc` 峰值约 200 MiB。

### 长 ASCII 查询的兜底

2 个廉价操作的变体数随串长和邻键数二次增长（纯 ASCII 长串可达数千）。
但 4 个廉价操作全部保持长度，这类候选必然与查询等长。当“长度为 n 的
词条桶整体 DP 一遍”比展开 2 廉价层更便宜时，直接扫描该长度桶；
若该长度根本没有词条，则跳过 2 廉价层。判定与调用见
`Engine._candidate_ids`，中文长查询因此仍是亚毫秒级，
`abcdefghijklmnopqrst` 约 25 ms。

## 打分与排序

- `F = ⌊100 × bit_length(freq) / bit_length(Fmax)⌋`，构建期预算；
- `D = max(0, 100 − 12 × cost)`；
- `P = min(100, 25 × LCP)`，LCP 在 casefold 串上按码点计；
- 总分 `40F + 45D + 15P`。

排序键固定为 `(−总分, −频次, 代价, 词条)`，词条比较即 Unicode 码点序，
等频等价候选的次序唯一。用 `heapq.nsmallest(top, …)` 截断，
`total_matched` 统计截断前全部命中数。

## 合并与归一化

词典 UTF-8（可带 BOM），空行与 `#` 行忽略；条目与查询都先去首尾空白
（Python 的 `str.strip()` 同样处理 U+3000 全角空格），比较键再做
`casefold()`。同一键取频次最大者，同频取原始词形码点序更小者。
原始词形用于输出与展示。

## 复杂度

设词条数 V、平均词长 L、词条签名数 `1 + L + C(L,2)`：

- 构建：生成 O(V·L²) 个签名并对 64 个分片排序，实测约 2.7 s；
- 内存：O(V·L²) 个打包整数 + O(V·L) 字符，实测峰值约 200 MiB；
- 查询：签名查找 O(K log(V·L²))，K 为查询侧去重后签名数
  （中文常见词约几十、纯 ASCII 长词另走长度桶），之后对候选集做
  带早退 DP；实测平均 0.9 ms、p95 2.3 ms、最坏 28 ms。

## 页面

`web/index.html` + `app.js`（ES module）+ `style.css`，无构建、无依赖。
页面只渲染 `data.json`：顶部指标板（词典文件、词条数、最大频次、加载耗时、
内存、p50/p95/最坏延迟、最慢单条查询），下方每条查询展示候选词、频次、
代价、总分与三项分解；零命中查询单独高亮。前端不做任何重排或重算。
